Glossary

217 essential terms, defined plainly. Want to memorize them? Try the flashcards.

ABCDEFGHIJKLMNOPQRSTVWZ#

A

Accessibility tree
A structured representation of UI elements exposed for assistive technology. Web and desktop agents use it as a compact, text-based alternative or complement to screenshots. → Computer-Use & Browser Agents
Action space
The set of actions available to an agent. For LLM agents it is usually defined by the tools it is given, plus the option of replying in text. → Tool Use & Function Calling
Agent Card
In A2A, a JSON document an agent publishes to describe its identity, capabilities, skills, endpoint and authentication requirements, enabling discovery by other agents. → Protocols: MCP, A2A & Interoperability
Agent framework
A library that supplies building blocks for agents, such as loops, tool abstractions, memory, orchestration and tracing. Examples include LangGraph, the OpenAI Agents SDK and the Claude Agent SDK. → Frameworks & SDKs Compared
Agent loop (Agentic loop, Tool-use loop)
The core cycle of an agent: call the model, execute any tools it requests, feed the results back, and repeat until the model produces a final answer or a stopping condition (step, time or cost budget) is hit. → The Agent Loop
Agent Skills (Skills)
Packaged folders of instructions, scripts and resources that an agent discovers by short description and loads only when relevant, a form of progressive disclosure for procedural knowledge. → Context Engineering
Agent-computer interface (ACI)
The set of commands, tools and output formats an agent uses to interact with a computer. The SWE-agent paper showed that designing this interface for the model, not for humans, substantially improves performance. → Coding Agents
Agent2Agent protocol (A2A)
An open protocol (announced by Google in 2025, now under the Linux Foundation) for agents built by different vendors to discover each other, exchange messages and coordinate long-running tasks. → Protocols: MCP, A2A & Interoperability
Agentic RAG
Retrieval in which the agent decides when and what to search, issues multiple refined queries, and judges whether results suffice, rather than a single fixed retrieve-then-generate step. → Retrieval & Agentic RAG
Agentless
An approach (Xia et al., 2024) that fixes software issues with a fixed localize-repair-validate pipeline instead of an autonomous agent, showing simple workflows can be competitive. → Coding Agents
AGENTS.md (CLAUDE.md)
A convention of placing a Markdown file of project instructions (build commands, conventions, gotchas) in a repository for coding agents to read at startup; CLAUDE.md is the Claude Code equivalent. → Coding Agents
AI agent (Agent, LLM agent, Autonomous agent)
A system in which a language model dynamically directs its own process and tool use to accomplish a goal, observing the results of its actions and deciding what to do next. Distinct from a fixed workflow, where the steps are predefined in code. → What Is an AI Agent?
AI control
A research agenda for safety measures that remain effective even if the model is misaligned, such as trusted monitoring, restricted permissions and auditing of agent actions. → Safety, Alignment & Governance
Alignment
Making AI systems pursue the goals and values their designers and users intend, including being helpful, honest and harmless. → Safety, Alignment & Governance
Alignment faking
A model selectively complying with training objectives during training to avoid having its behavior modified, while behaving differently when unmonitored (Greenblatt et al., 2024). → Safety, Alignment & Governance
Approval gate (Confirmation step)
A checkpoint where the harness pauses before a consequential or irreversible action, such as a payment, deletion or external email, and waits for human confirmation. → Human-in-the-Loop & Agent UX
Attention (Self-attention)
The mechanism that lets a Transformer weigh how relevant each token in the context is when producing the next one. Its cost grows with context length, which is one reason long contexts are expensive. → LLMs: The Engine Inside Every Agent
Augmented LLM
The basic building block of agentic systems: a language model enhanced with retrieval, tools and memory that it can choose to use. → Workflow Patterns
Autonomy
The degree to which an agent decides its own steps without human approval. Autonomy is a spectrum, from a model suggesting a single action to an agent running for hours unattended. → What Is an AI Agent?
Autoregressive generation (Next-token prediction)
Producing output one token at a time, with each new token conditioned on all previous tokens. This is why output tokens are slower and pricier than input tokens. → LLMs: The Engine Inside Every Agent

B

Background agent (Asynchronous agent)
An agent that runs asynchronously, often in a cloud sandbox, on a delegated task and reports back with results such as a pull request, rather than working interactively. → Deploying & Operating Agents
Batch API (Message Batches)
An asynchronous API mode that processes large sets of requests within a time window (often up to 24 hours) at a substantial discount, suited to offline evals and bulk jobs. → Cost & Latency Optimization
BDI architecture (Belief-Desire-Intention)
A classical agent architecture built on Beliefs (what the agent knows), Desires (goals) and Intentions (committed plans). It influenced how modern agents separate state, goals and plans. → A Brief History of AI Agents
Benchmark
A standardized public eval used to compare systems. Benchmarks are useful signals but can saturate, leak into training data, or diverge from your real workload. → Agent Benchmarks
Best-of-N sampling
Generating N candidate outputs and selecting the best according to a verifier, reward model or judge. → Reasoning & Planning
Blackboard architecture (Shared scratchpad)
A coordination pattern, dating to early AI, in which agents communicate by reading from and writing to a shared workspace rather than messaging each other directly. → Multi-Agent Systems
BM25
A classic lexical ranking function based on term frequency and document length. Robust for exact terms, IDs and rare words that embeddings can miss. → Retrieval & Agentic RAG
BrowseComp
A benchmark from OpenAI (2025) of hard-to-find facts that require persistent, creative web browsing to locate, while being easy to verify. → Agent Benchmarks
Browser agent (Web agent)
An agent that navigates and acts on websites, using screenshots, the DOM or the accessibility tree as observations and clicks, typing and navigation as actions. → Computer-Use & Browser Agents

C

CaMeL
A defense (Debenedetti et al., 2025) that converts the trusted user query into a program, tracks data provenance with capabilities, and enforces policies so untrusted data cannot change control flow. → Agent Security & Prompt Injection
Chain-of-thought (CoT)
Prompting or training a model to write out intermediate reasoning steps before its answer (Wei et al., 2022), which markedly improves multi-step reasoning. → Reasoning & Planning
Chunking
Splitting documents into smaller passages before embedding them. Chunk size and boundaries strongly affect retrieval quality. → Retrieval & Agentic RAG
Circuit breaker
A reliability pattern that stops calling a failing dependency for a cool-down period after repeated errors, preventing cascading failures and wasted spend. → Reliability & Durable Execution
CoALA
Cognitive Architectures for Language Agents (Sumers et al., 2023): a framework that organizes agents by modular memory (working, episodic, semantic, procedural), internal and external actions, and a decision loop. → Single-Agent Architectures
Code execution tool (Code interpreter)
A tool that lets the model write and run code in a sandbox, giving it calculation, data analysis and file manipulation abilities. → Tool Use & Function Calling
Code-based grader
A deterministic check, such as unit tests, string or schema matching, or a database state comparison, used to score agent outputs. Preferred whenever the task allows it. → Evaluating Agents
CodeAct (Code as action)
Using executable code as the agent's action format instead of JSON tool calls (Wang et al., 2024), letting one action compose many operations with loops and variables. → Tool Use & Function Calling
Coding agent
An agent that reads, writes and runs code in a repository, using tools such as file editing, search, a shell and tests to complete software tasks. → Coding Agents
Compaction (Context compression, Summarization)
Summarizing or condensing an agent's conversation history when it nears the context limit, then continuing with the summary in place of the full history. → Context Engineering
Compounding error
The way per-step failure probabilities multiply over long tasks: at 95% per-step reliability, a 20-step task succeeds end-to-end only about 36% of the time. → Agents vs. Workflows: When (Not) to Build an Agent
Computer use (GUI agent)
A capability in which a model operates a graphical computer by viewing screenshots and issuing mouse and keyboard actions. → Computer-Use & Browser Agents
Confused deputy
A security flaw in which a privileged program is tricked into misusing its authority on behalf of a less-privileged party, the classic shape of prompt injection against tool-using agents. → Agent Security & Prompt Injection
Constitutional AI
Anthropic's method (Bai et al., 2022) of training harmlessness from a written set of principles, using model self-critique and AI feedback instead of human labels for harms. → Safety, Alignment & Governance
Constrained decoding
Enforcing a grammar or schema at generation time by masking tokens that would violate it, guaranteeing syntactically valid structured output. → Structured Outputs & Control Flow
Context editing (Tool result clearing)
Selectively removing stale content from the context, such as old tool results or thinking blocks, while keeping the rest of the conversation intact. → Context Engineering
Context engineering
The discipline of curating the smallest high-signal set of tokens (instructions, tools, examples, history, retrieved data) for each model call, across the many turns of an agent run. → Context Engineering
Context isolation
Giving each subtask its own clean context (for example via subagents) so irrelevant tokens from other work do not distract the model. → Multi-Agent Systems
Context rot
The degradation of a model's recall and reasoning as its context grows longer, even well within the advertised window limit. → Context Engineering
Context window
The maximum number of tokens a model can consider in one request, including the system prompt, tools, conversation history and its own output. → LLMs: The Engine Inside Every Agent
Contextual retrieval
An Anthropic technique of prepending a short, model-generated explanation of each chunk's place in its document before embedding and BM25 indexing, reducing retrieval failures. → Retrieval & Agentic RAG
Corrigibility
The property of an AI system that accepts correction, modification or shutdown by its overseers rather than resisting it. → Safety, Alignment & Governance
Cost per task
The total spend to complete one task end-to-end, including all model calls, retries and tools. More meaningful for agents than cost per call. → Cost & Latency Optimization

D

Data contamination (Benchmark contamination)
Benchmark items leaking into a model's training data, inflating scores without reflecting real capability. → Agent Benchmarks
Data exfiltration
Unauthorized transfer of data out of a system, for example an injected agent embedding secrets in a URL, image link or outbound request. → Agent Security & Prompt Injection
Deep research
A class of agent that performs many searches and reads over minutes to hours, then writes a cited report on a complex question. → Deep Research Agents
Determinism (Nondeterminism)
Producing the same output for the same input. LLM calls are generally nondeterministic, so agents need evals over repeated runs and idempotent tools. → Reliability & Durable Execution
Distillation
Training a smaller student model to imitate a larger teacher's outputs or reasoning traces, transferring much of its capability at lower cost. → Training Agentic Models
DPO
Direct Preference Optimization (Rafailov et al., 2023): learning from preference pairs with a simple classification-style loss, without training a separate reward model or running RL. → Training Agentic Models
Dual LLM pattern
A defense proposed by Simon Willison: a privileged LLM that plans and calls tools never sees untrusted text, which is handled by a quarantined LLM whose outputs are passed around only as opaque variables. → Agent Security & Prompt Injection
Durable execution
Running long workflows so that each step's result is persisted and the run can resume after crashes or restarts without redoing completed work. → Deploying & Operating Agents

E

Egress control (Network allowlist)
Restricting which network destinations an agent's tools and sandbox can reach, usually via an allowlist, to close exfiltration channels. → Guardrails, Permissions & Sandboxing
Embedding (Embedding model, Vector embedding)
A dense vector representation of text (or images), produced by an embedding model, in which semantically similar inputs are close together. Embeddings power semantic search and retrieval. → Retrieval & Agentic RAG
Environment
Everything outside the agent that it perceives and acts on: files, APIs, a browser, a terminal, a user. The environment returns observations in response to actions. → What Is an AI Agent?
Episodic memory
Memory of specific past events or interactions, such as "last Tuesday the deploy failed because of X", often used for few-shot recall or reflection. → Memory Systems
Error analysis
Systematically reading failing traces, labeling failure modes and counting them, to decide what to fix next. Usually the highest-value eval activity. → Evaluating Agents
Eval (Evaluation)
A repeatable test of an AI system: a set of tasks, a way to run the system on them, and grading logic that scores the outputs or trajectories. → Evaluating Agents
Evaluator-optimizer (Generator-critic)
A loop in which one LLM generates a response and another evaluates it with feedback, iterating until the evaluator is satisfied or a limit is reached. → Workflow Patterns
Excessive agency
An OWASP LLM risk category: giving an LLM system more functionality, permissions or autonomy than it needs, so that errors or manipulation cause real harm. → Agent Security & Prompt Injection
Exponential backoff
Retrying failed requests with waits that grow exponentially (usually with random jitter), to ride out rate limits and transient errors without hammering the service. → Reliability & Durable Execution
Extended thinking (Adaptive thinking, Thinking)
A model feature that exposes a reasoning phase before the final answer. With adaptive thinking the model decides how much to think, steered by an effort setting rather than a fixed token budget. → Reasoning & Planning

F

Fallback
A predefined alternative when a step fails, such as another model, a cached answer, a simpler workflow or escalation to a human. → Reliability & Durable Execution
Few-shot prompting (In-context examples)
Including a handful of worked input-output examples in the prompt to show the model the desired behavior or format. → Prompt Engineering for Agents

G

GAIA
A benchmark (Mialon et al., 2023) of real-world questions that are simple for humans but require general assistants to combine reasoning, web browsing, multimodality and tool use. → Agent Benchmarks
Golden dataset
A curated set of representative inputs with expected outputs or grading criteria, used as the backbone of an eval suite. → Evaluating Agents
Graph-based orchestration (State graph)
Defining an agent or workflow as an explicit state graph of nodes (LLM calls, tools, code) and edges (transitions), as in LangGraph, for control, persistence and resumability. → Frameworks & SDKs Compared
GraphRAG
Retrieval over a knowledge graph extracted from the corpus, with community summaries that help answer global questions spanning many documents (Edge et al., 2024). → Retrieval & Agentic RAG
Grounding
Tying model outputs to verifiable sources such as retrieved documents, tool results or the screen, so claims can be checked and hallucination reduced. → Retrieval & Agentic RAG
GRPO
Group Relative Policy Optimization (introduced in DeepSeekMath, 2024): an RL algorithm that scores each sample relative to a group of samples for the same prompt, removing the need for a value model. → Training Agentic Models
Guardrail (Guardrails)
A check that runs alongside or around the model, such as input or output classifiers, policy rules or schema validation, to block unsafe, off-topic or malformed behavior. → Guardrails, Permissions & Sandboxing

H

Hallucination (Confabulation)
Model output that is fluent and confident but factually wrong or unsupported by the provided sources, such as an invented citation or API. → LLMs: The Engine Inside Every Agent
Handoff
Transferring control of a conversation from one agent to another, typically along with the relevant context, as in customer-service triage. → Multi-Agent Systems
Harness (Agent harness, Scaffold, Scaffolding)
The code around a model that turns it into an agent: the loop, tool execution, context management, permissions, retries and stopping logic. The same model can perform very differently in different harnesses. → The Agent Loop
Human-in-the-loop (HITL)
A design in which a human must review or approve certain agent actions or outputs before they take effect. → Human-in-the-Loop & Agent UX
Human-on-the-loop
A design in which the agent acts autonomously while a human monitors and can intervene or stop it, rather than approving each step. → Human-in-the-Loop & Agent UX
Hybrid search
Combining lexical search (such as BM25) with semantic vector search and fusing the rankings, usually outperforming either alone. → Retrieval & Agentic RAG
HyDE
Hypothetical Document Embeddings: generating a hypothetical answer to a query and embedding that, instead of the query, to retrieve similar real documents. → Retrieval & Agentic RAG

I

Idempotency
The property that repeating an operation has the same effect as doing it once. Idempotent tools make retries after timeouts safe. → Reliability & Durable Execution
In-context learning
A model's ability to pick up a task from instructions and examples in its prompt, without any weight updates (Brown et al., 2020). → LLMs: The Engine Inside Every Agent
Indirect prompt injection
Prompt injection delivered through content the agent reads, such as web pages, emails, documents or tool results, rather than typed by the user (Greshake et al., 2023). → Agent Security & Prompt Injection
Instruction hierarchy
Training models to prioritize instructions by privilege, system over user over third-party content (Wallace et al., 2024), to resist injected instructions. → Agent Security & Prompt Injection
Interleaved thinking
Reasoning that happens between tool calls, not only before the first one, so the model can reflect on each tool result before choosing its next action. → Reasoning & Planning

J

Jailbreak
An input crafted to make a model violate its own safety policies. Unlike prompt injection, the attacker is usually the user. → Agent Security & Prompt Injection
JSON Schema
A standard vocabulary for describing the shape of JSON data. It is how tool inputs and structured outputs are specified to a model. → Tool Use & Function Calling
Just-in-time retrieval (Progressive disclosure)
Keeping lightweight references (file paths, URLs, IDs) in context and letting the agent load full content with tools only when needed, instead of pre-loading everything. → Context Engineering

K

Knowledge cutoff
The date after which a model's training data contains little or no information. Agents use search and retrieval tools to work past it. → LLMs: The Engine Inside Every Agent
KV cache
Stored attention keys and values for tokens already processed, so they need not be recomputed. Reusing it across requests is the mechanism behind prompt caching. → Cost & Latency Optimization

L

Language Agent Tree Search (LATS, MCTS for agents)
LATS (Zhou et al., 2023) applies Monte Carlo tree search to agent trajectories, using the LLM as action proposer, value estimator and self-reflector. → Reasoning & Planning
Large language model (LLM)
A neural network, usually a Transformer, trained on vast text corpora to predict the next token. Scaled up and post-trained, it can follow instructions, reason and call tools. → LLMs: The Engine Inside Every Agent
Least privilege
Granting an agent only the minimum tools, permissions, data and credentials needed for its task, limiting the damage of mistakes or compromise. → Agent Security & Prompt Injection
Lethal trifecta
Simon Willison's term for the dangerous combination of access to private data, exposure to untrusted content, and the ability to communicate externally. An agent with all three can be tricked into exfiltrating data. → Agent Security & Prompt Injection
LLM-as-a-judge (LLM judge, Model-based grader)
Using a language model with a rubric to grade outputs that lack a simple programmatic check. Judges must be validated against human labels and watched for biases. → Evaluating Agents
LLMCompiler
A framework (Kim et al., 2023) that plans tool calls as a dependency graph and executes independent calls in parallel, reducing latency and cost. → Single-Agent Architectures
Long-horizon task
A task that requires many sequential steps or a long time to complete, where small per-step error rates compound and context management becomes critical. → Reliability & Durable Execution
Long-term memory
Information persisted outside the context window, in files, databases or vector stores, and retrieved into context when relevant across sessions. → Memory Systems
Loop detection (Doom loop)
Harness logic that notices an agent repeating the same actions or making no progress and intervenes, for example by stopping, nudging or escalating. → Reliability & Durable Execution
Lost in the middle
The finding (Liu et al., 2023) that models use information at the beginning and end of a long context better than information in the middle. → Context Engineering

M

max_tokens
The request parameter capping how many tokens the model may generate. Hitting it truncates output (stop_reason max_tokens), which can leave a tool call incomplete. → The Agent Loop
MCP client (MCP host)
The protocol component inside a host application (such as an IDE or chat app) that maintains a connection to one MCP server and relays its capabilities to the model. → Protocols: MCP, A2A & Interoperability
MCP server
A program that exposes tools, resources and prompts over the Model Context Protocol, for example wrapping a database, a SaaS API or the local filesystem. → Protocols: MCP, A2A & Interoperability
Memory poisoning
An attack in which malicious content is written into an agent's persistent memory so that it influences future sessions. → Agent Security & Prompt Injection
Meta Agent Search (ADAS)
The algorithm from ADAS (Hu et al., 2024) in which a meta agent iteratively writes new agent designs in code, evaluates them and archives the best. → Self-Improving & Open-Ended Agents
Model cascade (Model routing)
Routing each request to the cheapest model likely to handle it and escalating to stronger models only when needed. → Cost & Latency Optimization
Model Context Protocol (MCP)
An open protocol (introduced by Anthropic in 2024) that standardizes how applications expose tools, resources and prompts to LLM clients, so any compliant agent can use any compliant server. → Protocols: MCP, A2A & Interoperability
MRKL
Modular Reasoning, Knowledge and Language (Karpas et al., 2022): an early neuro-symbolic architecture that routes queries from an LLM to expert modules such as calculators and APIs. → A Brief History of AI Agents
Multi-agent debate
Several model instances propose answers, critique each other over rounds and converge on a final answer (Du et al., 2023), aiming to improve factuality and reasoning. → Multi-Agent Systems
Multi-agent system (MAS)
A system of multiple LLM agents, each with its own prompt, tools or context, that collaborate through messages, a shared state or an orchestrator. → Multi-Agent Systems

N

Needle in a haystack (NIAH)
A long-context test that hides a specific fact in a large body of text and asks the model to retrieve it. Passing it does not imply robust long-context reasoning. → Context Engineering

O

Observability
The ability to understand what an agent did and why, from traces, logs, metrics and evaluations of production runs. → Observability & Debugging
Observation
Information the agent receives from its environment after an action, such as a tool result, a screenshot or an error message. → The Agent Loop
Online evaluation
Measuring agent quality on live production traffic via sampling, user feedback, guardrail triggers and A/B tests, complementing offline evals. → Observability & Debugging
OpenTelemetry (OTel)
A vendor-neutral open standard for traces, metrics and logs. Its GenAI semantic conventions define standard attributes for recording LLM and agent operations. → Observability & Debugging
Orchestrator (Lead agent, Supervisor)
The component (a model or code) that breaks a task into pieces, delegates them to workers or subagents, and combines their results. → Workflow Patterns
Orchestrator-workers
A pattern in which a central LLM dynamically decides the subtasks, delegates them to worker LLMs, and synthesizes their results; the subtasks are not known in advance. → Workflow Patterns
OSWorld
A benchmark (Xie et al., 2024) of open-ended tasks in real desktop operating systems and applications, with execution-based evaluation, used to measure computer-use agents. → Agent Benchmarks

P

Parallel tool calls
Multiple independent tool calls emitted in a single model turn and executed concurrently, with all results returned together in the next message. → Tool Use & Function Calling
Parallelization (Sectioning, Voting)
A workflow that runs LLM calls simultaneously, either sectioning a task into independent parts or voting by running the same task several times. → Workflow Patterns
pass@k
The probability that at least one of k sampled attempts solves a task (Chen et al., 2021). It rewards capability: a 50% per-attempt success rate gives pass@3 of 87.5%. → Evaluating Agents
pass^k (pass-hat-k)
The probability that all k independent attempts succeed, introduced with τ-bench to measure consistency. A 90% per-attempt rate gives pass^8 of about 43%. → Evaluating Agents
pause_turn
A stop reason indicating a server-side tool loop paused mid-turn; the client resumes by sending the conversation back, including the paused assistant turn, without adding a new user message. → The Agent Loop
Plan-and-execute (Plan-and-solve, Planner-executor)
An architecture that first produces an explicit multi-step plan, then executes the steps (often with a cheaper model), re-planning when results diverge. → Single-Agent Architectures
Poka-yoke
Mistake-proofing: designing tool interfaces so that wrong usage is hard or impossible, for example requiring absolute file paths or enumerated values instead of free text. → Designing Great Tools (The Agent–Computer Interface)
Post-training
Everything done to a pretrained model to make it useful and safe: instruction tuning, preference optimization, reinforcement learning, and tool-use training. → Training Agentic Models
PPO
Proximal Policy Optimization (Schulman et al., 2017): a policy-gradient RL algorithm that limits how far each update moves the policy; the classic optimizer in RLHF. → Training Agentic Models
Procedural memory
Memory of how to do things: skills, routines and instructions. In LLM agents it lives in model weights, system prompts, skill files and code. → Memory Systems
Process reward model (PRM)
A reward model that scores each intermediate reasoning step rather than only the final answer, which an outcome reward model (ORM) does (see Lightman et al., 2023, "Let's Verify Step by Step"). → Training Agentic Models
Prompt caching
Reusing the processed state of an identical prompt prefix across requests, so cached tokens are billed at a fraction of the normal input price and processed faster. → Cost & Latency Optimization
Prompt chaining
A workflow that decomposes a task into a fixed sequence of LLM calls, each processing the previous output, optionally with programmatic checks (gates) between steps. → Workflow Patterns
Prompt engineering
The practice of writing and iterating on instructions, examples and structure to get reliable model behavior. In agents it is a subset of context engineering. → Prompt Engineering for Agents
Prompt injection
An attack in which text crafted by an attacker is interpreted by the model as instructions, overriding the developer's or user's intent. → Agent Security & Prompt Injection

Q

Query rewriting (Query expansion)
Reformulating a user question, for example by expanding, decomposing or clarifying it, before retrieval to improve recall. → Retrieval & Agentic RAG

R

Rational agent
In classical AI (Russell & Norvig), an agent that selects the action expected to maximize its performance measure given its percepts and knowledge. → A Brief History of AI Agents
ReAct (Reason + Act)
A prompting pattern (Yao et al., 2022) in which the model interleaves reasoning traces (Thought) with actions (tool calls) and observations, letting reasoning guide actions and observations update reasoning. → Single-Agent Architectures
Reasoning model (Thinking model)
An LLM trained, typically with reinforcement learning, to produce an extended internal chain of reasoning before answering, trading more tokens and latency for accuracy on hard problems. → Reasoning & Planning
Red teaming
Adversarially probing a system, manually or with automated attackers, to discover failures and vulnerabilities before real users or attackers do. → Safety, Alignment & Governance
Reflection
An agent periodically synthesizing higher-level insights from its raw memories or past attempts, as in Generative Agents (Park et al., 2023), whose simulated characters combine a memory stream, reflection and planning. → Memory Systems
Reflexion
A technique (Shinn et al., 2023) in which an agent writes verbal self-reflections on failed attempts and stores them in memory to improve later attempts, without weight updates. → Single-Agent Architectures
Refusal
A model declining to complete a request on safety or policy grounds. APIs may signal it with a dedicated stop reason, and agent loops must not execute tool calls from a refused turn. → The Agent Loop
Regression eval
An eval of tasks the system already handles, run on every change to catch breakage. It should stay near 100%; capability evals, by contrast, measure progress on hard tasks. → Evaluating Agents
Reranker (Cross-encoder)
A model, typically a cross-encoder, that rescores a shortlist of retrieved passages against the query for higher precision than the first-stage retriever. → Retrieval & Agentic RAG
Retrieval-augmented generation (RAG)
Retrieving relevant documents from an external corpus at query time and placing them in the prompt so the model answers from them (Lewis et al., 2020). → Retrieval & Agentic RAG
Reward hacking (Specification gaming)
An agent achieving high reward by exploiting flaws in the reward signal or tests, such as special-casing tests, instead of doing the intended task. → Safety, Alignment & Governance
Reward model
A model trained to score outputs according to human (or AI) preferences, providing the reward signal for reinforcement learning. → Training Agentic Models
ReWOO
Reasoning WithOut Observation (Xu et al., 2023): a planner writes the whole tool plan with placeholders up front, workers fill them in, and a solver composes the answer, saving tokens versus ReAct. → Single-Agent Architectures
RL environment
A task setup used for agent training, comprising tools, a starting state, a task, and a reward function or verifier that scores the agent's trajectory. → Training Agentic Models
RLAIF
Reinforcement learning from AI feedback: using model-generated preference labels, often guided by principles, in place of or alongside human labels. → Training Agentic Models
RLHF (Reinforcement learning from human feedback)
Reinforcement learning from human feedback: train a reward model on human preference comparisons, then optimize the policy model against it, as in InstructGPT (Ouyang et al., 2022). → Training Agentic Models
RLVR (Reinforcement learning with verifiable rewards)
Reinforcement learning with verifiable rewards: RL where the reward comes from automatic checks, such as correct math answers or passing tests, the recipe behind modern reasoning models. → Training Agentic Models
Routing
A workflow in which a classifier (an LLM or code) sends each input to a specialized prompt, tool set or model, for example easy queries to a cheaper model. → Workflow Patterns
Rubric
Explicit criteria and scoring guidance used by human or LLM graders, ideally with specific pass/fail checks rather than vague quality scales. → Evaluating Agents

S

Sandbagging
A model strategically underperforming on evaluations, for example to appear less capable than it is. → Safety, Alignment & Governance
Sandbox
An isolated execution environment, such as a container, microVM or restricted process, that limits what agent-run code can access, protecting the host, data and network. → Guardrails, Permissions & Sandboxing
Scaling laws
Empirical power-law relationships between model performance and compute, data and parameters (Kaplan et al., 2020; Hoffmann et al., 2022), used to plan training runs. → LLMs: The Engine Inside Every Agent
Scheming (Deceptive alignment)
A hypothesized failure mode in which a model covertly pursues goals misaligned with its developers while appearing aligned, for example by hiding capabilities or evading oversight. → Safety, Alignment & Governance
Self-consistency
Sampling several independent reasoning paths and taking the majority answer (Wang et al., 2022), trading extra compute for accuracy. → Reasoning & Planning
Self-correction
A model revising its own output. Research shows intrinsic self-correction without external feedback is unreliable; it works best with grounded signals like test results or tool errors. → Reasoning & Planning
Self-improving agent
An agent that improves its own prompts, tools, code or weights based on its experience, from skill libraries (Voyager) to agents rewriting their own scaffolding. → Self-Improving & Open-Ended Agents
Self-RAG
A method (Asai et al., 2023) that trains a model to decide when to retrieve and to critique its own generations for relevance and support using reflection tokens. → Retrieval & Agentic RAG
Self-Refine
An iterative loop (Madaan et al., 2023) in which the same model generates an output, critiques it, and revises it until a stopping condition. → Workflow Patterns
Semantic memory
Memory of general facts and knowledge, such as user preferences or domain facts, decoupled from when they were learned. → Memory Systems
Server tool (Server-side tool)
A tool executed by the model provider's infrastructure, such as web search or code execution, rather than by your application. Long server-tool turns can pause and need resuming. → Tool Use & Function Calling
Set-of-Mark prompting
Overlaying numbered marks on regions of a screenshot so a vision model can refer to UI elements by label rather than by raw pixel coordinates. → Computer-Use & Browser Agents
Short-term memory (Working memory)
Information an agent holds within its current context window, chiefly the conversation and recent tool results. It is lost when the context is reset or compacted. → Memory Systems
Simulated user (User simulator)
An LLM playing the user's role in multi-turn evals, as in τ-bench, so conversational agents can be tested at scale. → Evaluating Agents
Skill library
A growing store of reusable, verified programs or procedures an agent has learned, retrieved for new tasks, as in Voyager. → Self-Improving & Open-Ended Agents
Spotlighting
Prompt-level defenses that mark untrusted content, by delimiting, data-marking or encoding it, so the model can distinguish data from instructions. Helpful but not a guarantee. → Agent Security & Prompt Injection
Step budget (Max steps, Iteration limit)
A hard limit on iterations, tokens, time or money for an agent run, the harness's safety net against runaway loops and costs. → The Agent Loop
Stop reason (stop_reason)
A field on each model response saying why generation ended, for example end_turn, tool_use, max_tokens, pause_turn, refusal or stop_sequence. The agent loop branches on it. → The Agent Loop
Streaming
Receiving a model's output incrementally as it is generated, typically via server-sent events, so users and harnesses can act before the response completes. → Cost & Latency Optimization
Structured note-taking (Agentic memory, Progress file)
Having an agent write progress notes, to-do lists or state files outside the context window and re-read them later, preserving continuity across compactions or sessions. → Context Engineering
Structured outputs (JSON mode)
Constraining a model's output to match a given JSON Schema, so responses can be parsed reliably by code. → Structured Outputs & Control Flow
Subagent
An agent spawned by another agent to handle a subtask in its own fresh context window, returning only a condensed result. Subagents isolate context and enable parallel work. → Multi-Agent Systems
Supervised fine-tuning (SFT, Instruction tuning)
Further training a pretrained model on curated input-output examples, such as instructions with good responses or successful agent trajectories. → Training Agentic Models
SWE-bench (SWE-bench Verified)
A benchmark (Jimenez et al., 2023) of real GitHub issues from Python repositories; an agent must produce a patch that makes the hidden tests pass. SWE-bench Verified is a human-validated subset of 500 tasks. → Agent Benchmarks
Sycophancy
A model's tendency to tell users what they want to hear, agreeing with mistaken claims or abandoning correct answers under pushback. → Safety, Alignment & Governance
Synthetic data
Training or evaluation data generated by models rather than collected from humans, such as synthetic tool-use dialogues or task variations. → Training Agentic Models
System prompt (System message)
Instructions placed before the conversation that set the agent's role, goals, constraints, tool guidance and output format. It is the highest-leverage piece of prompt text in an agent. → Prompt Engineering for Agents

T

Task decomposition
Breaking a complex goal into smaller subtasks that can be solved sequentially or in parallel, by the model itself or by an orchestrator. → Reasoning & Planning
Temperature
A sampling setting that sharpens (low) or flattens (high) the probability distribution over next tokens. Many current reasoning models fix sampling parameters and reject user-set values. → LLMs: The Engine Inside Every Agent
Test-time compute (Inference-time compute, Test-time scaling)
Extra computation spent while answering, such as longer reasoning, sampling many candidates or search, to improve accuracy without changing model weights. → Reasoning & Planning
Time horizon (50% time horizon)
METR's metric for agent capability: the length of task, measured by how long it takes skilled humans, that a model completes with a given success rate (typically 50%). → Agent Benchmarks
Time to first token (TTFT)
Latency from sending a request until the first output token arrives. It dominates perceived responsiveness in chat and voice agents. → Cost & Latency Optimization
Token
The unit of text a model reads and writes, typically a word piece. Context limits, pricing and speed are all measured in tokens. → LLMs: The Engine Inside Every Agent
Tool call (tool_use block)
A structured request emitted by the model, such as a tool_use block with an id, a tool name and JSON input, asking the harness to run a tool. → Tool Use & Function Calling
Tool choice
A request setting that controls whether the model may call tools (auto) or must not (none). Some APIs also allow forcing a specific tool, though newer models may restrict this. → Tool Use & Function Calling
Tool definition (Tool schema)
The name, natural-language description and input JSON Schema that tell a model what a tool does and how to call it. Its quality largely determines whether the tool is used correctly. → Designing Great Tools (The Agent–Computer Interface)
Tool namespacing
Grouping related tools under shared name prefixes (for example github_ or browser_) so the model can tell similar tools apart and the harness can enable or mask groups. → Designing Great Tools (The Agent–Computer Interface)
Tool poisoning (Rug pull)
An attack in which malicious instructions are hidden in a tool's description or metadata (for example an MCP server's), or a trusted tool changes behavior after approval. → Agent Security & Prompt Injection
Tool result (tool_result)
The output of a tool sent back to the model, linked to the originating call by its id and optionally flagged as an error so the model can recover. → Tool Use & Function Calling
Tool search (Deferred tool loading)
Loading tool definitions on demand, by letting the model search a catalog, instead of placing hundreds of definitions in every prompt. → Designing Great Tools (The Agent–Computer Interface)
Tool use (Function calling)
A model's ability to request calls to external functions by emitting a structured call (name plus arguments) that the application executes and returns results for. → Tool Use & Function Calling
Toolformer
A model (Schick et al., 2023) that taught itself when and how to call APIs by self-supervised filtering of candidate calls that improved next-token prediction. → Tool Use & Function Calling
Trace
A structured, timestamped record of one agent run, typically a tree of spans covering model calls, tool calls and their inputs, outputs, latency and token usage. → Observability & Debugging
Trajectory (Rollout, Transcript)
The full sequence of model outputs, tool calls and observations an agent produces while working on a task. Trajectories are the raw material for debugging, evaluation and training. → Evaluating Agents
Trajectory evaluation
Grading the path an agent took, such as tool choices, step count, errors and policy compliance, in addition to the final outcome. → Evaluating Agents
Transformer
The neural network architecture (Vaswani et al., 2017) behind modern LLMs, built on self-attention layers that let every token draw information from every earlier token. → LLMs: The Engine Inside Every Agent
Tree of Thoughts (ToT)
A framework (Yao et al., 2023) in which the model generates and evaluates multiple partial reasoning steps and searches over them with breadth- or depth-first search and backtracking. → Reasoning & Planning

V

Vector database (Vector store)
A datastore optimized for storing embeddings and running fast nearest-neighbor similarity queries over them. → Retrieval & Agentic RAG
Verifier
A component that checks a candidate output, such as unit tests, a type checker, a rules engine or a trained model. Reliable verifiers are what make search, retries and RL effective. → Reasoning & Planning
Virtual context management (MemGPT)
The MemGPT idea (Packer et al., 2023) of treating the context window like RAM and external storage like disk, with the agent paging information in and out via function calls. → Memory Systems
Voice activity detection (VAD, Endpointing)
Detecting when a user starts and stops speaking; together with turn-detection models it decides when a voice agent should respond. → Customer-Facing & Voice Agents
Voice agent
A conversational agent that listens and speaks in real time, either via a cascade of speech-to-text, LLM and text-to-speech, or via a native speech-to-speech model. → Customer-Facing & Voice Agents
Voyager
A lifelong-learning Minecraft agent (Wang et al., 2023) with an automatic curriculum, an iterative prompting loop and a skill library of executable code. → Self-Improving & Open-Ended Agents

W

WebArena
A benchmark (Zhou et al., 2023) of realistic tasks on self-hosted websites (e-commerce, forums, code hosting, CMS) with functional, execution-based checks. → Agent Benchmarks
Workflow
An LLM system in which models and tools are orchestrated through predefined code paths. Workflows trade flexibility for predictability, cost control and easier debugging. → Workflow Patterns
World model
An internal model of how an environment works, used to predict the consequences of actions and plan ahead. → Open Problems & The Road Ahead

Z

Zero-shot chain-of-thought
Eliciting step-by-step reasoning without examples, famously by appending a phrase like "Let's think step by step" (Kojima et al., 2022). → Reasoning & Planning

A benchmark (Yao et al., 2024) of tool-agent-user interaction in domains like airline and retail, with a simulated user and domain policies; it introduced the pass^k metric. τ²-bench adds dual-control environments. → Agent Benchmarks
